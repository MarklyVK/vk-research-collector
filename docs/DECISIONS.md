# Архитектурные решения

## ADR-001. PostgreSQL как единственное хранилище состояния

Очередь, прогресс поиска, пакеты и классификация хранятся в PostgreSQL. Это
обеспечивает возобновление без отдельного брокера и соответствует лимитам сервера.

## ADR-002. Идемпотентность ограничениями БД

VK ID группы, ключевое слово внутри предметной области, связь группы с ключевым
словом и элемент пакета защищаются уникальными ограничениями PostgreSQL.

## ADR-003. Ручная классификация фиксированными пакетами

Состав пакета записывается один раз. Импорт сначала полностью валидируется, затем
применяется одной транзакцией; повторная успешная классификация пакета запрещена.

## ADR-004. Безопасный первый этап

Команда `collection start` только показывает будущий набор групп. Она не создаёт
заданий загрузки постов, подписчиков или пользователей.

## ADR-005. PostgreSQL queue и page-level transactions

Второй этап использует существующий PostgreSQL без брокера. Захват выполняется через
`FOR UPDATE SKIP LOCKED`, lease восстанавливается по timeout, а данные и checkpoint
одной страницы фиксируются одной транзакцией.

## ADR-006. Консервативная минимизация профиля

Первая реализация профиля сохраняет только VK ID, публичное имя, screen name и флаги
доступности/deactivation. Демографические и контактные поля не нужны для заявленного
связного анализа и не запрашиваются.

## ADR-007. Подписки выключены до отдельного capacity gate

Код и fake-тесты подписок входят во второй этап, но массовое планирование по умолчанию
выключено: потенциальная кардинальность несовместима с диском 10 GB без измеренного pilot.

## ADR-008. Устаревшая граница stage 1

Файлы контекста и `AGENTS.md` всё ещё описывают первый этап. Явное задание от
28.07.2026 требует второй этап и является текущим scope; запреты на scraping, secrets,
опасное удаление и тяжёлую инфраструктуру остаются в силе.

## ADR-009. Capacity report связан с точной конфигурацией

Первый pilot 200/1000 дал прогноз 13,54 GiB и не разрешил запуск. Новый plan-key хранит
все scopes и лимиты; capacity report применяется только при точном совпадении runtime.
Изолированный repilot разрешил 100 постов, 200 участников и профили с прогнозом
3,89 GiB. Subscriptions остаются отдельным запрещённым scope.

## ADR-010. Автономный Compose worker

Долгий сбор выполняет `collector-worker` с `restart: unless-stopped`. Он не хранит
состояние в памяти/локальном файле, ожидает только full run с успешным capacity gate и
использует PostgreSQL lease/checkpoints. Это позволяет Codex завершиться без остановки
сбора.
